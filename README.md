# Peropix Lkit mobile ver.

NovelAI 이미지를 **폰 하나로 대량 생성**하는 안드로이드 앱. 서버가 필요 없습니다.

챗봇 캐릭터용 에셋처럼 *같은 캐릭터를 감정·상황별로 수십~수백 장* 뽑아야 할 때를 위해
만들었습니다. 슬롯마다 다른 프롬프트를 넣고 한 번에 돌린 뒤, 결과를 슬롯별로 훑으며
버릴 것과 남길 것을 갈라냅니다.

> **필요한 것**: NovelAI 구독과 API 키. 키는 첫 실행 때 넣고 이 기기에만 저장됩니다.
> 앱에 박혀 있지 않으니 APK 를 남에게 줘도 키가 따라가지 않습니다.

Capacitor 로 감싼 하이브리드 앱이라 화면과 로직은 전부 `www/` 안의 HTML·JS 입니다.

- 슬롯마다 다른 프롬프트로 한 번에 연속 생성
- 인물을 몇 명이든 쌓아 두고 **켠 인물만** 전송
- 저장 위치를 **폰 / PC / VPS** 중에 선택
- PeroFix 프롬프트 JSON 가져오기 (폰에 있는 `.json` 파일을 골라도 됩니다)
- 자주 쓰는 작가·퀄리티 태그를 이름 붙여 모아 두기

## ⚠ 서명 키에 대해

`android/peropix.keystore` 가 저장소에 들어 있고, **암호도 `android/app/build.gradle` 에
그대로 적혀 있습니다.** 실수가 아닙니다.

안드로이드는 서명이 다른 APK 를 덮어 설치하지 못합니다. 자동 생성되는 `debug.keystore`
는 기기마다·빌드마다 달라서, 그대로 두면 새로 만든 APK 가 매번 "앱이 설치되지 않았습니다"
가 됩니다. 키를 하나로 고정해 두면 어디서 빌드하든 계속 덮어 설치됩니다.

**이 키를 신뢰의 근거로 삼지 마세요.** 누구나 같은 키로 서명할 수 있으므로,
서명이 맞는다는 것이 "이 저장소에서 나온 APK" 라는 뜻은 아닙니다. 직접 쓰실 거면
직접 만든 키로 바꾸시고, 배포하실 거면 GitHub Secrets 에 넣어 쓰세요.

```bash
keytool -genkeypair -keystore android/peropix.keystore -alias peropix   -keyalg RSA -keysize 2048 -validity 10950
```

## 만들기

```bash
npm install
```

```bash
npx cap sync android
```

그다음 Android Studio 로 열거나 (`npx cap open android`), 명령줄로 바로 뽑습니다.

```bash
cd android && ./gradlew assembleDebug
```

결과물: `android/app/build/outputs/apk/debug/app-debug.apk`

> **JDK 는 17 또는 21 이어야 합니다.** Android Studio 번들 JDK 가 Java 25 면
> Gradle 8.14 가 읽지 못해 `Unsupported class file major version 69` 로 죽습니다.
> 그때는 `~/.gradle/gradle.properties` 에 `org.gradle.java.home=<JDK 21 경로>` 를 적으세요.

## 폰에 설치하기

Play 스토어에 올리지 않았으므로 **APK 를 직접 넣습니다.** 세 단계입니다.

**1. APK 를 폰으로 옮깁니다**

아무 방법이나 됩니다. USB 케이블, 카톡 "나에게 보내기", 구글 드라이브, 메일 첨부.
파일은 여기 있습니다.

```
android/app/build/outputs/apk/debug/app-debug.apk
```

USB 로 옮기실 거면 이 명령이 제일 빠릅니다 (개발자 옵션 · USB 디버깅을 켜 두었을 때).

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

`-r` 은 "이미 깔려 있으면 덮어쓰기" 입니다. **설정은 그대로 유지**되므로 업데이트할 때
지우고 다시 깔 필요가 없습니다.

**2. "출처를 알 수 없는 앱" 을 허용합니다**

APK 를 누르면 안드로이드가 한 번 막습니다. 뜨는 안내를 따라
**설정 → 이 앱(파일 관리자나 브라우저) → "이 출처 허용"** 을 켜면 됩니다.
스토어를 거치지 않은 앱은 전부 이 과정을 거칩니다. 한 번만 하면 됩니다.

**3. 설치 후 첫 실행**

| 순서 | 화면 |
|---|---|
| 1 | **NovelAI API 키** 입력, 키가 실제로 통하는지 바로 확인합니다 |
| 2 | **권한**, 알림(생성 완료 알림용)과 파일 저장을 확인합니다 |
| 3 | 메인 화면 |

키는 이 기기에만 저장되고, **다음 실행부터는 묻지 않습니다.**

> **API 키 발급**: NovelAI 웹사이트 → User Settings → Account →
> Get Persistent API Token. `pst-` 로 시작하는 문자열입니다.

### 업데이트할 때

새로 빌드한 APK 를 그냥 덮어 설치하면 됩니다. **지우지 마세요**, 지우면 API 키·슬롯·
프리셋이 함께 날아갑니다. 덮어 설치는 설정을 유지합니다.

단, 서명이 다른 APK 는 덮어쓰지 못합니다. 다른 PC 에서 빌드한 것을 설치하려면
기존 앱을 지워야 합니다 (설정도 함께 사라집니다).

## 프롬프트는 세 축입니다

데스크톱판과 같은 구조입니다. **서로 섞이지 않습니다.**

| 축 | 무엇 | NAI 페이로드 |
|---|---|---|
| **공통 프롬프트** | 장면 전체에 걸리는 태그 | `prompt` / `v4_prompt.base_caption` |
| **캐릭터 프롬프트** | 인물별 태그 + 인물별 UC + 5×5 좌표 | `characterPrompts[]` / `v4_prompt.char_captions[]` |
| **생성 슬롯** | 한 장씩 바꿔 가며 뽑을 변주 | 슬롯마다 위 둘 중 하나에 합쳐짐 |

슬롯 프롬프트를 **공통에 붙일지 캐릭터에 붙일지**는 "슬롯 프롬프트를 어디에 붙일까" 에서
고릅니다. **기본값은 "캐릭터에"**, 데스크톱판과 같습니다. 여기가 다르면 같은 설정인데
다른 그림이 나옵니다.

### 인물은 쌓아 두고 골라 씁니다

인물 목록에는 **몇 명이든** 넣어 둘 수 있습니다. 생성 슬롯과 똑같이 인물 카드마다
동그란 원이 있고, **켠 인물만 전송됩니다.** 끄면 카드 전체가 어두워집니다.

**꺼 둔 인물은 모델 상한 자리를 차지하지 않습니다.** 8명을 넣어 두고 앞 2명을 꺼 두면
3~8번이 나갑니다. 자주 쓰는 인물을 지우지 않고 남겨 둘 수 있습니다.

한 번에 **켠** 인물이 모델 상한(V4.5 6명 · V5 32명)을 넘을 때만 빨간 경고가 뜹니다.
조용히 잘라 보내면 돈만 쓰고 다른 그림이 나오기 때문입니다.

인물별로 슬롯 프롬프트를 붙이지 않으려면 가져오는 JSON 에 `"skipSlotPrompt": true` 를
넣습니다. 폰 화면에는 조작이 없습니다. PC 에서 JSON 을 쓰는 쪽이 정합니다.

### 인터넷이 끊겼을 때: 못 만든 것만 다시

배치를 돌리는 도중 인터넷이 끊기면 남은 장이 줄줄이 깨집니다. 그때 처음부터 다시 돌리면
**이미 나온 장까지 또 뽑아 Anlas 를 두 번 씁니다.** 결과 화면 맨 위의

> **"못 만든 3장 다시 생성"**

을 누르면 **그 장들만** 같은 설정으로 이어 뽑습니다.

- **이미 나온 장은 건드리지 않습니다.** 다시 뽑은 장은 원래 자리에 그대로 갈아 끼워져
  묶음과 순서가 흐트러지지 않습니다
- **중지**로 손도 못 댄 장까지 함께 셉니다. "실패 2장 + 중지로 안 만든 5장"
- 그림이 있는데 **저장만 실패한 장은 대상이 아닙니다** (다시 뽑을 필요 없이 뷰어에서
  저장하면 됩니다)
- 도는 중에 같은 버튼이 **"중지"** 가 됩니다. 또 멈추면 남은 장을 다시 들고 있습니다
- 위쪽 **"실패"** 필터로 깨진 장만 모아 볼 수 있습니다

와일드카드는 다시 뽑을 때 **새로 굴립니다** (시드도 어차피 새로 나오므로, 깨진 조합을
그대로 되살릴 이유가 없습니다).

### 인물이 많고 슬롯이 적을 때: "한 명씩 돌리기"

인물 8명을 각각 따로 뽑으려면 원래는 **한 명만 켜고 돌리고 → 끄고 다음 사람 켜고 돌리고** 를
여덟 번 해야 했습니다. 이 스위치를 켜면 그 왕복을 앱이 대신 합니다.

- 켠 인물을 **한 명씩** 보내고, **인물 수만큼 바퀴를 더 돕니다**, 인물 × 슬롯 × 배수
- 순서는 **인물 → 배수 → 슬롯**. 한 사람을 끝내고 다음 사람으로 가므로, 중간에 멈춰도
  앞쪽 인물은 통째로 끝나 있습니다
- 저장 경로에 **인물 폴더가 한 겹** 끼어듭니다. `작품/미아/1-1.png`, `작품/리사/1-1.png`.
  이게 없으면 미아의 1-1 과 리사의 1-1 이 같은 경로가 되어 `_2` 가 붙고, 나중에 어느 것이
  누구인지 알 수 없습니다. 자리를 직접 정하려면 이름 규칙에 `{char}` 를 넣으면 됩니다
- 결과 화면에서 **"인물 · 슬롯"** 으로 묶여 보입니다
- 인핸스 · ×4 · 배경 합성으로 만든 파생본도 **같은 인물 폴더**로 갑니다
- 한 장에 한 명만 실리므로 **모델의 인원 상한과 무관합니다** (V4.5 6명 · V5 32명)

스위치는 본문(캐릭터 프롬프트 아래)과 **인물 서랍 안** 두 곳에 있고, 어느 쪽을 눌러도 같이
움직입니다. 켜면 몇 장이 나오는지 바로 적어 줍니다. "인물 3 × 슬롯 2 = 6장".

> 예상 Anlas 도 이제 **실제로 뽑을 이미지 수**로 셉니다 (배수와 이 바퀴까지 포함). 전에는 슬롯
> 수만 세어서, 배수를 3으로 두면 실제의 1/3 로 적혀 있었습니다.

## 앱 아이콘

원본은 `icon.png` (900×900, 배경 `#00a6ca`). 고쳐서 다시 만들려면:

```bash
python tools/make_icons.py icon.png
```

밀도별 런처 아이콘·원형 아이콘·적응형 아이콘을 전부 만듭니다.

적응형 아이콘은 기기 모양(원형·둥근사각 등)에 따라 **바깥이 잘립니다.** 그래서
배경을 뚫어 글자만 남기고 `SAFE_RATIO`(0.58) 안에 넣습니다. 안드로이드가 보장하는
안전 영역이 108dp 중 지름 66dp 원이라 그렇습니다. 0.72 로 뒀더니 실제로 P 위쪽과
Kit 아래가 잘렸습니다.

## 폴더 관리

상단 🗂 버튼. **폰 · PC · VPS** 를 같은 화면에서 다룹니다.

- 폴더를 눌러 안으로 들어가고, ↑ 상위로 나옵니다
- 폴더마다 안에 몇 장 있는지 보여 줍니다 (매트릭스 채움 확인용)
- ✎ 이름 바꾸기 · 🗑 지우기 · + 새 폴더
- **비어 있지 않은 폴더는 두 번 묻습니다.** 수백 장이 한 번에 날아가는 사고를 막습니다

## 배경 합성

투명 배경으로 뽑은 인물을 **배경 그림 위에 얹습니다.** 통신이 없어 **Anlas 가 들지 않고**
인터넷도 필요 없습니다. 전부 폰 안에서 끝납니다.

- 뷰어의 **"배경"**, 지금 보는 한 장
- 결과 화면의 **"배경 합성"** 은 지금 필터로 **보이는 것 전부**

원본은 그대로 두고 **새 장으로 붙습니다** (인핸스·×4 와 같습니다). "배경" 꼬리표가 붙고
"최종본" 필터에 들어갑니다.

### 자리 잡는 법

| 배치 | 무엇 |
|---|---|
| **고정** | 모든 장을 **같은 자리에** 세웁니다 |
| **무작위** | 장마다 크기와 자리를 다르게 뽑되, **인물이 잘리지 않는 범위 안에서만** 뽑습니다 |
| 그대로 얹기 | 원본 크기 그대로. 인물과 배경 크기가 같을 때 |
| 직접 맞추기 | 크기·가로·세로를 손으로 |

고정과 무작위는 **알파 경계**(실제로 그려진 부분)를 찾아 계산합니다. 슬롯마다 인물이 잡힌
크기와 여백이 달라도 "인물 높이 92% · 바닥 여백 2%" 처럼 **비율로** 맞으므로, 수십 장이
같은 자리에 섭니다. 슬라이더로 손대는 것은 이 비율입니다.

무작위는 **"위아래로도 무작위"** 를 꺼 두면 가로로만 움직이고 발은 바닥에 붙습니다.
**"다시 굴려 보기"** 로 미리보기를 다시 뽑아 볼 수 있습니다. 실제로는 장마다 다른 값이
나오고, 무엇이 나왔는지는 저장 정보(`compose.seed`)에 남습니다.

### ⚠ 투명 배경의 알파

NAI 는 **"Straight Alpha" 를 끄면 미리 곱해진 알파**로 내려줍니다. 그대로 얹으면
알파가 두 번 곱해져 **인물 윤곽이 검게 탑니다.** 그래서 합치기 전에 픽셀을 훑어 어느 쪽인지
판별하고(미리 곱해진 그림은 모든 픽셀이 `RGB ≤ A`), 필요하면 되돌린 뒤 겹칩니다.
판별이 틀린 것 같으면 "세부 설정 → 알파 처리" 에서 못 박을 수 있습니다.

### 인핸스·업스케일해도 투명은 지켜집니다

NAI 에 보내는 베이스 이미지는 알파를 **흰 배경에 평탄화**해서 보냅니다 (데스크톱판과 같은
절차). 그래서 예전에는 투명 배경으로 뽑아 놓고 인핸스하면 **배경이 하얗게 붙어** 돌아왔고,
투명하게 뽑은 보람이 없었습니다. 지금은,

- 그 그림을 뽑을 때의 **투명 배경 설정을 그대로 이어** 요청합니다 (지금 화면의 체크박스가
  아니라, 그 사이에 체크를 껐거나 모델을 바꿨을 수 있습니다)
- 돌아온 그림이 **불투명하면 원본의 알파를 다시 씌우고**, 가장자리에 섞인 배경색을 걷어냅니다
  (걷어내지 않으면 머리카락 둘레에 흰 테가 남습니다). 섞인 배경색은 **그림에서 알아냅니다**.
  인핸스는 흰색, 업스케일은 검정으로 오는 등 경로마다 다르기 때문입니다
- NAI 가 알파를 담아 돌려주면 그것을 그대로 씁니다
- **×4 업스케일도 같습니다**

### 그 밖

- 결과 크기는 **인물 크기**(기본) 또는 **배경 크기** 중에 고릅니다
- 배경은 결과를 **채우거나**(넘치는 쪽을 자름) **늘입니다**
- 축소는 생성 쪽과 같은 lanczos3 입니다. 폰에서 한 장에 1~2초쯤 걸리고, 같은 배경으로
  여러 장을 돌리면 **줄여 둔 배경을 재사용**합니다
- NAI 가 붙여 둔 PNG 메타데이터(Title·Source 등)는 **원본에서 옮겨 심습니다**

## 저장 위치와 이름

### 저장할지 말지

생성 옵션의 **"생성하면 바로 저장"** 으로 정합니다.

| 켬 (기본) | 끔 |
|---|---|
| 나오는 대로 전부 저장 | 아무 데도 쓰지 않음 |
| 대량 생산에 적합 | 뷰어에서 마음에 드는 것만 골라 저장 |

끈 상태에서는 앱을 나가면 저장하지 않은 이미지는 사라집니다.

### 전체화면 뷰어

- 결과 이미지를 누르면 열립니다
- **좌우로 밀어** 이전/다음 장 (짧게 밀거나 세로로 밀면 넘어가지 않습니다)
- **위로 밀면 버리기 · 아래로 밀면 저장.** 미는 동안 화면 한가운데에 **"버리기"·"저장"**
  이 크게 뜨고, 기준을 넘으면 한 번 커집니다. 손가락에 가려 아래쪽 작은 글씨는 안 보입니다
- **확대**: 손가락 두 개로 벌리거나, **두 번 누르거나**, 오른쪽 아래 **− 1.0× ＋** 단추.
  확대한 채로 끌면 **그림이 움직입니다**(이동). 확대 중에는 밀기가 꺼집니다. 확대한 채로
  밀다가 버려지면 되돌릴 수 없기 때문입니다. 장을 넘기면 확대는 풀립니다
- **버리면 그 슬롯의 다음 장**으로 넘어갑니다. 그 슬롯이 비면 **다음 슬롯의 첫 장**으로
  갑니다 (훑으면서 버리는 흐름이라, 버릴 때마다 손으로 다시 찾아 들어가면 안 됩니다)
- 상단 **저장** 버튼으로 그 장만 저장. 이미 저장된 장은 "저장됨" 으로 잠깁니다
- 실패한 장은 뷰어에서 건너뜁니다
- PC 미리보기에서는 휠로 확대, `+` `-` `0` 키로도 됩니다

### 어디에 저장할지

"저장 위치와 이름" 패널에서 고릅니다.

| 위치 | 저장되는 곳 |
|---|---|
| **이 폰** | 문서/PeroPix/ 아래 |
| **PC · VPS** | 그쪽에 띄워 둔 수신함 (`tools/receiver.py`) |

PC 와 VPS 는 같은 방식으로 다룹니다. 주소만 다릅니다. 설정 화면에서 여러 개 등록해 두고
필요할 때 골라 쓸 수 있습니다.

### 이름 규칙

기본은 PeroFix 정리 관례를 따릅니다.

```
{folder}/{label}.png     →     미아/1-3.png
```

쓸 수 있는 토큰: `{folder}` `{label}` `{seq}` `{seed}` `{date}` `{time}` `{model}`

`{folder}` 는 메인 화면 맨 위 **"폴더 이름"** 칸의 값입니다.
예전 이름인 `{persona}` 도 그대로 읽히므로 저장해 둔 규칙은 깨지지 않습니다.

- 같은 이름이 겹치면 덮어쓰지 않고 `_2`, `_3` 이 붙습니다 (앱과 수신함 양쪽에서 막습니다)
- 윈도우가 싫어하는 글자·예약 이름(`CON`, `NUL` 등)은 자동으로 비켜 갑니다
- 하이픈은 건드리지 않습니다. `1-3` 같은 좌표 라벨이 어긋나지 않게

## PeroFix JSON 가져오기

슬롯 위 **"JSON 가져오기"** 버튼. Claude Code·Codex·Gemini 가 만든 파일을 읽습니다.

가져오기 화면 맨 위 **"폰에서 JSON 파일 고르기"** 를 누르면 파일 관리자가 열립니다.
클립보드보다 이 길이 낫습니다. 긴 JSON 은 복사하다 잘리고, 안드로이드는 앱을 오갈 때
클립보드를 비우기도 합니다. 붙여넣기 칸은 아래에 그대로 있습니다.

```json
{
  "name": "미아 · 일상 모드",
  "prefix": "1girl, silver hair, blue eyes",
  "slots": [
    { "name": "1-1", "content": "bedroom, morning light, medium shot, smile", "locked": false }
  ]
}
```

| JSON | 앱 |
|---|---|
| `prefix` | 공통 프롬프트 |
| `slots[].name` | 슬롯 이름 (저장 파일명에 쓰임) |
| `slots[].content` | 슬롯 프롬프트 |

- **캐릭터 JSON** 도 같은 화면에서 가져옵니다 (`characters[]` 의 `content`·`uc`·`coord`·
  `enabled`·`skipSlotPrompt` 를 읽습니다)
- "기존 슬롯 교체" 와 "뒤에 추가" 둘 다 있습니다
- ` ```json ` 표시를 같이 붙여넣어도 알아서 벗겨냅니다
- 같은 이름이 둘이면 `_2` 를 붙여 갈라 줍니다 (파일 겹침 방지)
- `locked` 는 앱이 쓰지 않지만 값은 보존합니다

## 원격 작업: 올려 둔 작업을 폰이 받아 간다

Claude Code 같은 도구가 PC·VPS 수신함에 **작업**(무엇을 뽑을지)을 올려 두면, 폰 앱이 그것을
받아 뽑고 결과를 같은 수신함에 올립니다. 올린 쪽은 결과를 파일로 바로 확인합니다.

> **API 키는 폰에만 있습니다.** 올라가는 것은 프롬프트와 설정뿐이고, NovelAI 를 부르는 것도
> Anlas 를 쓰는 것도 언제나 폰입니다. 수신함은 쪽지함일 뿐입니다.

### 폰에서

상단 **📥 원격 작업** 버튼. 받아 올 수신함을 고르면 기다리는 작업이 뜹니다.

- 작업마다 **몇 장짜리인지** 미리 적혀 있습니다 (슬롯 × 인물 × 배수)
- **"실행"** 을 누르면 한 번 더 묻고 (`약 N장을 뽑고 Anlas 를 씁니다`) 시작합니다
- 실행하면 **지금 슬롯·인물·폴더 이름이 그 작업 것으로 바뀝니다** (가져오기와 같습니다)
- 저장 위치는 **그 수신함으로 자동 전환**되고 자동 저장이 켜집니다. 결과가 올린 쪽에 보여야
  왕복이 완성되기 때문입니다
- **"받으면 바로 실행"** 을 켜면 묻지 않고 돕니다. 묻지 않고 Anlas 를 쓰므로 기본은 꺼짐입니다
- 진행(3/8)과 끝난 뒤의 파일 목록이 수신함에 기록됩니다
- 안드로이드가 백그라운드를 재우므로 **앱이 켜져 있는 동안만** 돕니다

### GitHub 을 지시함으로 쓰기 (서버 없이)

수신함을 띄울 곳이 없어도 됩니다. **내 GitHub 저장소 하나**를 지시함으로 씁니다.
AI(Claude Code · Codex 등)가 거기에 JSON 을 커밋해 두면 폰이 읽어 생성합니다.

**이 저장소(peropix-mobile)를 지시함으로 쓰지 마세요.** 공개 저장소라 프롬프트가
그대로 남습니다. **자기 저장소를 새로 만들어** 쓰세요. 앱이 만드는 법을 안내합니다.

#### 1. 저장소 만들기

앱의 **📥 원격 작업 → 어디서 지시를 받을까 → "GitHub 지시함" → "처음이면, 지시함
저장소 만들기"** 를 폅니다.

1. **"GitHub 에서 새 저장소 만들기"**, 이름은 아무거나. **Private 을 권합니다**
2. **"AI 에게 시킬 말 복사"**, 복사한 문구를 Claude Code · Codex 에 그대로 붙여넣으면
   규약 파일(`AGENTS.md` · `CLAUDE.md`)과 폴더·예시를 만들어 커밋해 줍니다
3. 비공개로 만들었다면 **읽기 전용 토큰**을 넣습니다
   (Settings → Developer settings → Fine-grained tokens → 그 저장소에 Contents: Read)
4. **저장소** 칸에 `내이름/저장소이름` 을 적고 **저장하고 확인**

규약 전문은 이 저장소의 [`docs/inbox/AGENTS.md`](docs/inbox/AGENTS.md) ·
[`docs/inbox/CLAUDE.md`](docs/inbox/CLAUDE.md) 에 있습니다. 그대로 복사해 넣어도 됩니다.

#### 2. 폴더 구조 (작품마다 하나씩)

```
<내 지시함 저장소>/
  AGENTS.md · CLAUDE.md      ← AI 가 읽는 규약
  미아/
    characters/미아.json      ← 인물 (그 작품 안에서 공용)
    slots/일상.json           ← 슬롯 묶음 = **작업 하나**
    slots/H.json
  리사/
    characters/리사.json
    slots/교복.json
```

- 첫 폴더 이름이 **작품 이름**이자 폰에 저장될 **폴더 이름**입니다
- 인물 폴더는 `characters` `character` `캐릭터` `인물`, 슬롯 폴더는 `slots` `slot` `슬롯`
  `작업` `jobs`, 아무거나 씁니다 (작품 폴더 바로 아래 `.json` 도 슬롯으로 봅니다)
- 루트에 그냥 둔 `.json` 과 점으로 시작하는 폴더(`.github`)는 무시합니다

**슬롯 파일**, `미아/slots/일상.json`

```json
{
  "name": "미아 · 일상",
  "prefix": "1girl, silver hair, masterpiece",
  "slots": [
    { "name": "1-1", "content": "smile, bedroom" },
    { "name": "1-2", "content": "angry, classroom" }
  ],
  "options": { "count_per_slot": 1 }
}
```

**인물 파일**: `미아/characters/미아.json`

```json
{ "name": "미아", "content": "1girl, silver hair, blue eyes" }
```

`options` 는 아는 값만 받습니다. 모델·크기·steps·cfg·샘플러·UC·퀄리티·네거티브·배수·
한 명 모드·투명 배경·저장 형식·Variety+·시드.

#### 3. 언제 뽑히나 (트리거)

- **슬롯 파일이 새로 생기거나 내용이 바뀌면** 그것이 새 작업이 됩니다. 판단은 GitHub 이
  주는 **blob SHA** 로 합니다. 내용이 같으면 SHA 도 같아서, 커밋을 다시 해도 같은 작업을
  두 번 뽑지 않습니다
- **인물 파일을 고치는 것은 작업을 만들지 않습니다.** 인물 한 줄 고칠 때마다 그 작품의
  슬롯이 전부 다시 도는 것은 돈이 나가는 사고입니다. 다음에 그 작품을 돌릴 때 최신
  인물이 자동으로 쓰입니다
- 앱이 그 저장소를 볼 때 시작됩니다 (원격 작업 화면을 열거나, "받으면 바로 실행" 을
  켜 두면 주기적으로). GitHub 이 폰을 깨우지는 못합니다

#### 4. 지키는 선

- **목록은 트리 API 한 번**으로 가져옵니다 (`?recursive=1`). 폴더마다 부르면 토큰 없는
  한도(시간당 60번)를 금방 칩니다. 파일 내용은 `raw`(CDN)로 받아 한도를 쓰지 않습니다
- **앱은 저장소에 쓰지 않습니다.** 폰에 쓰기 토큰을 넣지 않기 때문입니다. 이미 한 작업은
  **폰이 기억**하므로 파일을 지우지 않아도 다시 돌지 않습니다
  ("한 것 기억 지우기" 로 되살릴 수 있습니다)
- NovelAI API 키는 **폰에만** 있습니다. 저장소에는 지시만 오갑니다
- 공개 저장소에 적은 프롬프트는 **누구나 봅니다.** 가릴 것이 있으면 비공개로
- 결과는 GitHub 으로 되돌아가지 않습니다. 앱의 저장 위치(폰 또는 수신함)에 그대로 남습니다

### PC · Claude 쪽에서

```bash
python tools/job.py --url 192.168.0.5:8770 --token 토큰 push --file 작업.json
python tools/job.py --url ... --token ... list          # 상태 보기

작업 JSON 은 **PeroFix 가져오기와 같은 모양**입니다. 거기에 `folder` 와 `options` 만 얹습니다.

  "folder": "미아",

`options` 는 **아는 값만** 받습니다 (모델·크기·steps·cfg·샘플러·UC·퀄리티·네거티브·배수·
한 명 모드·투명 배경·저장 형식·Variety+·시드). 모르는 값은 무시합니다. 페이로드가 뒤틀리지
않게 하려는 것입니다.

### 수신함 엔드포인트 (작업 큐)

| | |
|---|---|
| `POST /jobs` | 작업 올리기 `{name, spec}` |
| `GET /jobs?status=pending` | 목록 |
| `POST /jobs/claim` | 기다리는 것 하나를 집어 간다 (폰이 부릅니다) |
| `POST /jobs/update` | 진행·결과 알리기 |
| `POST /jobs/delete` | 지우기 |
| `POST /score` | 그림들의 특징 벡터 `{kind, paths\|data}` (`score.py` 를 깔았을 때만) |

작업은 이미지 폴더 안 `.jobs/` 에 JSON 으로 쌓이고, **파일 목록·폴더 화면에서는 숨깁니다**
(매트릭스 채움 셈이 틀어지지 않게). 토큰 검사는 다른 엔드포인트와 같습니다.

`claim` 은 집는 순간 `running` 으로 바꿉니다. 폰이 둘이어도 같은 작업을 두 번 뽑지
않습니다 (돈이 두 배로 나갑니다).

## 수신함 설치 (PC · VPS)

### 한 줄로 (권장)

SSH 로 붙어서 이것만 붙여넣으면 끝입니다.

```bash
curl -fsSL https://raw.githubusercontent.com/lulus-cat/peropix-mobile/main/tools/deploy/install.sh | sudo bash -s -- --open
```

파일을 올릴 필요도, 방화벽을 열 필요도, 창을 켜 둘 필요도 없습니다. 스크립트가
`receiver.py` 와 `score.py` 를 받아 `/opt/peropix` 에 놓고, 전용 사용자를 만들고,
비밀번호를 만들고, systemd 서비스로 등록하고(로그아웃해도 재부팅해도 계속 돕니다),
`ufw` 나 `firewalld` 가 켜져 있으면 포트를 열어 줍니다. 끝나면 앱에 그대로 붙여넣을
`peropix://주소:포트#비밀번호` 한 줄을 찍어 줍니다.

앱 설정의 **원격 저장 대상** 칸에 이 명령을 복사하는 단추가 있습니다.

`--open` 을 빼면 `127.0.0.1` 에만 붙습니다. VPN(Tailscale·WireGuard) 안에서만 쓸 때 그렇게 합니다.

```bash
--port 9000          포트 바꾸기
--host peropix.내도메인   앱에 찍어 줄 주소를 직접 정하기
--dry-run            아무것도 안 고치고 무엇을 할지만 보기
--uninstall          서비스와 프로그램 지우기 (이미지·비밀번호는 남습니다)
```

두 가지는 스크립트가 못 합니다. **클라우드 업체의 방화벽**(Contabo·AWS·Oracle 콘솔의
인바운드 규칙)은 서버 밖에 있어서 손댈 수 없고, **TLS** 는 도메인이 있어야 붙일 수
있습니다. 인터넷에 열린 VPS 라면 아래 「⚠ VPS 라면 반드시 암호화할 것」 을 보세요.

> `curl … | sudo bash` 가 꺼림칙하면 당연합니다. 받을 스크립트는
> [tools/deploy/install.sh](tools/deploy/install.sh) 에서 그대로 읽을 수 있고,
> `--dry-run` 을 붙이면 아무것도 안 고치고 무엇을 할지만 찍습니다.

### 직접 깔기

`tools/receiver.py` 는 표준 라이브러리만 씁니다. **설치할 것이 없습니다** (Python 3.8+).

일관성 검사를 이 서버에 맡기려면 `tools/score.py` 를 옆에 두고 `pip install torch
transformers pillow` 를 한 번 하면 됩니다. 안 해도 나머지는 그대로 돌아갑니다.

### 1. 띄우기

```bash
python tools/receiver.py --root ./images
```

이게 전부입니다. **비밀번호를 만들 필요가 없습니다**, 처음 켤 때 하나 만들어
`images/.peropix-token` (권한 0600) 에 넣어 두고, 다음부터 그대로 씁니다. VPS 에 다시
들어가 "그 토큰 뭐였지" 를 할 일이 없습니다.

띄우면 화면에 이런 줄이 나옵니다.

```
peropix://192.168.0.5:8770#stvmBob1quChz13XOT9jrOW_1_Y_BdXhGpPdp5RvDNE
```

앱의 **설정 → 원격 저장 대상 → 한 줄로 붙여넣기** 에 그대로 넣으면 이름·주소·비밀번호가
한 번에 채워집니다. 손으로 옮겨 적을 것이 없습니다. 기본 포트는 8770 입니다.

**`receiver.py` 는 앱 안에서 꺼냅니다.** 설정 → 원격 저장 대상 → "receiver.py 복사" ·
"파일로 저장". SSH 로 붙어서 `cat > receiver.py` 하고 붙여넣은 뒤 Ctrl+D 를 누르면
끝입니다. 저장소를 뒤지지 않는 이유는, 앱 안의 것이 **지금 그 앱과 짝이 맞는 판**이기
때문입니다 (저장소 기본 가지에는 옛 판이 있을 수 있습니다). 사본이 조용히 낡지 않도록
`test_receiver.py` 가 두 파일이 같은지 대조합니다.

직접 정하고 싶으면 `--token` 을 주면 됩니다 (16자 이상).
**영문·숫자·기호만 됩니다.** 비밀번호는 HTTP 헤더로 실려 나가는데 헤더에는 한글이
담기지 않아, 넣어 두면 받는 쪽은 멀쩡한데 폰에서만 안 되는 상태가 됩니다. 수신함이
띄울 때 미리 막습니다.

### 왜 SSH 비밀번호로 안 하나

수신함은 SSH 가 아니라 **HTTP** 로 이야기합니다. 이유는 셋입니다.

- 앱은 Capacitor 로 감싼 WebView 라 자바스크립트가 돕니다. **자바스크립트에는 SSH 가
  없습니다.** 붙이려면 안드로이드 네이티브 모듈을 따로 써야 하는데, 지금은 화면과 로직이
  전부 `www/` 안의 HTML·JS 라서 PC 브라우저에서 그대로 돌려 검사할 수 있습니다.
  SSH 경로는 그 검사를 통째로 못 합니다.
- **서버 비밀번호를 폰에 넣는 것이 더 위험합니다.** 그것 하나면 서버 전체에 셸이 열립니다.
  수신함 비밀번호는 그 이미지 폴더 하나만 엽니다. 폰을 잃어버렸을 때 새는 것의 크기가
  다릅니다.
- 지금 쓰는 것도 결국 **비밀번호**입니다. 서버 전체가 아니라 수신함 것일 뿐이고,
  붙여넣기 한 줄로 넘어가므로 칠 일도 없습니다.

### 2. ⚠ VPS 라면 반드시 암호화할 것

평문 HTTP 로 인터넷에 열면 **토큰과 이미지가 그대로 노출됩니다.** 셋 중 하나를 쓰세요.

| 방법 | 설명 |
|---|---|
| **리버스 프록시 (권장)** | Caddy 나 nginx 로 TLS 를 씌우고 수신함은 `--host 127.0.0.1` 로만 연다 |
| **직접 인증서** | `--cert cert.pem --key key.pem` |
| **VPN** | Tailscale·WireGuard 안에서만 연다 |

집 LAN 안의 PC 라면 평문도 무방합니다.

Caddy 예시 (도메인이 있을 때, 인증서를 알아서 받아 갱신합니다):

```
img.내도메인.com {
    reverse_proxy 127.0.0.1:8770
}
```

### 수신함이 지키는 것

- 토큰이 없거나 틀리면 전부 거부 (상수시간 비교)
- 경로 탈출(`../`, 절대경로, 인코딩 우회) 차단, 저장 폴더 밖으로 절대 못 나감
- 이미지 확장자만 허용, 32MB 상한
- 같은 이름은 덮어쓰지 않고 `_2` 로 비킴
- 다 쓴 뒤 이름을 바꿔 옮김, 중간에 끊겨도 반쪽 파일이 남지 않음

## 일관성 검사

뽑은 그림들이 서로 얼마나 같은지 재 줍니다. 스무 장을 눈으로 훑어서는 두 장만 얼굴이
다른 것을 잘 못 잡아냅니다. 보통은 저장까지 다 하고 폴더에서 나란히 놓고 봐야 알아챕니다.

**그림체** 는 테스트 → 조합에서 씁니다. 한 조합에 두 장 이상 뽑아 두면 결과 아래에
"그림체 일관성 검사" 단추가 생깁니다. 조합마다 점수를 매기고 제일 고른 것부터 줄을
세워 줍니다. 별점이 "얼마나 마음에 드는가" 라면 이쪽은 "그 조합으로 계속 뽑아도 같은
화풍이 나오는가" 입니다. 둘은 다른 이야기라서 따로 보여 줍니다. 예쁜데 들쭉날쭉한
조합은 생각보다 흔합니다.

**인물** 은 대량생성 결과 화면에서 씁니다. 같은 사람끼리 묶어서 재고, 덜 닮은 장에
"인물 다름?" 표시를 붙입니다. 지우거나 "버릴 것" 으로 찍지는 않습니다. 닮았는지는
결국 사람 눈이 정하는 것이고 모델도 틀립니다. 여기를 보라고 짚어 줄 뿐입니다.

### 어디서 잴지 고르기

설정 → **일관성 검사** 에서 두 가지 중에 고릅니다. 기본은 꺼져 있습니다.

**이 폰에서.** 모델을 한 번 받아 두면(그림체 90MB, 인물 45MB) 다음부터는 인터넷 없이도
됩니다. 서버가 필요 없는 대신 오래된 폰에서는 느립니다. 받기 전에 얼마나 받는지 먼저
물어보니, Wi-Fi 에서 눌러 주세요.

**수신함에서.** PC 나 VPS 가 대신 잽니다. 폰은 아무것도 안 받습니다. 그 서버에
준비할 것이 조금 있습니다.

```bash
pip install torch transformers pillow      # CPU 만 있어도 됩니다
# score.py 를 receiver.py 와 같은 폴더에 두고
python3 receiver.py --root ./images
```

켤 때 `일관성 검사 : 켜짐` 이라고 나오면 된 것입니다. `score.py` 는 저장소를 뒤질 것
없이 앱 설정 화면에서 바로 꺼낼 수 있습니다(복사 또는 파일로 저장). 수신함을 등록하거나
"연결 확인" 을 누를 때 앱이 그 서버가 검사를 할 수 있는지 보고, 할 수 있으면 맡길지
그 자리에서 물어봅니다.

`receiver.py` 자체는 여전히 표준 라이브러리만 씁니다. 무거운 것은 전부 `score.py`
쪽에 있어서, 검사를 안 쓸 거면 예전처럼 받아서 바로 켜면 됩니다.

### 재는 방법

두 갈래 모두 하는 일은 특징 벡터를 뽑는 데까지입니다. 고른지 튀는지 판정하는 것은
앱의 `consistency.js` 한 곳입니다. 폰에서 뽑든 서버에서 뽑든 잣대가 하나라서, 서버를
껐다 켰다 해도 같은 그림의 점수가 흔들리지 않습니다.

점수는 절대값이 아니라 **그 묶음 안에서 얼마나 떨어졌는지** 로 봅니다. 포즈가 다 다른
배치는 원래 흩어지는 게 맞고, 같은 캐릭터 표정 세트는 붙어 있는 게 맞습니다. "0.8 이상이면
합격" 같은 기준을 못 박으면 판마다 엉뚱한 답이 나옵니다.

장수가 적으면 판정을 그대로 믿지 마세요. 표본이 n장일 때 z 값은 아무리 튀어도
(n-1)/√n 을 넘지 못합니다. 4장이면 1.5, 3장이면 1.155 입니다. 그래서 넉 장으로
"고르다" 가 나와도 우연일 수 있고, 그럴 때는 "장수가 적어 참고만 하세요" 를 같이
적어 둡니다. 기준도 그 장수에서 실제로 닿을 수 있는 값으로 낮춰 잡습니다.

**모델.** 그림체는 CLIP 이미지 인코더(화풍·색감·선에 민감), 인물은 DINOv2(배경과 포즈가
달라도 같은 사람인지에 강함)를 씁니다. 환경변수 `PEROPIX_STYLE_MODEL`,
`PEROPIX_ID_MODEL` 로 바꿔 끼울 수 있습니다.

## 작가 태그

작가 태그를 **실시간으로 확인**하고, 엄선해 모아 두고, 그림에서 "그 요소를 만든 범인"을

### 찾기: 반영율과 화풍

Danbooru 에 그때그때 물어봅니다. 목록을 앱에 넣어 두지 않으니 늘 최신입니다.
**토큰이 필요 없습니다** (비로그인으로 열려 있고 CORS 도 열려 있습니다).

- 이름·**별명**으로 자동완성 (픽시브 이름으로 찾아 들어와도 잡힙니다)
- **반영율**: 이미지 수로 매긴 다섯 등급. 정직하게 말하면 **추정**입니다. NAI 가 무엇을
  얼마나 배웠는지는 공개되지 않았습니다. 다만 학습이 Danbooru 를 바탕으로 한 이상
  그림 수가 곧 학습량이라, 이미지 수를 기준으로 쓰되 **"몇 장이라 이 등급인지"를 같이 적어**
  직접 판단하시게 했습니다
- 이미지 수가 많아도 **최근에 몰려 있으면** 학습 시점 이후라 안 먹을 수 있어서,
  "몇 %가 몇 년 이전인지"도 함께 적습니다
- 등급 분포 · 평균 연도 · 주로 그리는 판권 · 혼자/흑백/만화/가로 비율
- **특징 태그 ×N**: 남들보다 몇 배 자주 그리는가. 잦은 태그만 보면 어느 작가나
  1girl·solo 라 아무 정보가 없어서, 전체 평균과 견주어 튀는 것만 남깁니다
- 그림 미리보기. **수위를 골라서** 부릅니다 (전체 이용가만 / 가벼운 것까지 / 아슬한
  것까지 / 가리지 않음). 동영상은 뺍니다

### 서랍: 엄선 · 라벨 · 섞기

- **장르는 앱이 자동으로 매깁니다**: 배경 · 인물(여) · 인물(남) · 19금. 그 작가의 그림
  표본에서 재기 때문에 손이 안 갑니다.
  한 작가가 여러 장르에 걸칩니다(여성도 그리고 19금도 그린다). 그래서 하나를 고르는
  분류가 아니라 **여러 개가 붙는 표시**입니다. 하나로 몰아넣으면 "여성 인물 잘 그리는
  19금 작가"를 찾을 수 없습니다.
  남성은 `male_focus` 를 중심으로 봅니다. `1boy` 는 남녀가 함께 나온 그림에도 붙어서,
  그것만 세면 여성 위주 작가가 전부 "인물(남)"이 되어 버립니다.
- **라벨은 직접 붙입니다** ("두꺼운 선" "수채"). 장르(앱이 잰 것)와 다른 축이라 줄을
  나눠 두었고, 장르를 다시 재도 라벨은 지켜집니다
- **이름은 한 번만 적습니다.** "라벨 붙이기" 를 누르고 라벨을 하나 고르면, 그 뒤로는
  **작가 줄을 누르기만** 하면 붙었다 떨어집니다 (붙은 줄은 ✓). 작가마다 이름을 다시
  적게 하면 스무 명한테 붙이려고 스무 번을 타이핑하게 됩니다
- "보이는 작가 전부" 로 한꺼번에 붙입니다. 검색·즐겨찾기·장르와 같이 쓰면 "19금 작가
  전부에 '어두움' 붙이기" 가 한 번에 끝납니다. 다 붙어 있으면 같은 단추가 "전부 떼기"
  가 됩니다. 되돌릴 데가 같은 자리에 있어야 합니다
- 라벨 **이름 바꾸기·지우기**도 그 줄에서 합니다. 지워도 작가는 서랍에 남습니다
- **대량생성에서 저장해 둔 작가 태그 모음을 그대로 가져옵니다.** 이미 모아 둔 것이 있는데
  서랍에 담으려고 손으로 다시 찾아 넣는 것은 헛일입니다. 모음에 섞여 있는 퀄리티 태그는
  Danbooru 에 라벨를 물어 **작가인 것만** 남깁니다 (한 번에 다 묻습니다. 태그마다 부르면
  스무 개짜리 모음 하나에 스무 번이 나갑니다). 몇 명 담았고 몇 개를 뺐는지 적어 줍니다
- `artist:wlop` 처럼 적어 둔 것도 알아봅니다. `artist:` 는 Danbooru 의 **검색 문법**이지
  태그 이름이 아니라서, 그대로 물어보면 그런 태그가 없다고 나옵니다
- 즐겨찾기()와 이름 검색으로 좁혀 봅니다
- 눌러서 **섞기**에 넣고, 작가마다 **가중치**를 슬라이더로 정합니다. 한 조합에
  **20명까지**입니다. 그 위로는 한 이미지에 작가가 스무 명 넘게 들어가 화풍이 뭉개집니다
- 조합·깎기에서 고를 때는 **서랍 라벨대로 묶여** 나옵니다. 스무 명이 한 줄로 늘어서 있으면
  어느 것이 무엇인지 알 수가 없습니다. 한 사람이 라벨을 여러 개 가지면 양쪽에 다 나오고,
  어느 쪽을 눌러도 똑같이 켜집니다
- **"가중치 범위 정하기"**: 폭과 간격을 **단추로** 고릅니다 (좁게 / 보통 / 넓게 /
  아주 넓게, 간격 0.05 · 0.1 · 0.25). 폰에서 숫자 칸을 톡톡 치는 것이 성가셔서 그렇게
  했고, 꼭 필요하면 "숫자로 직접 적기"를 펴면 됩니다. 기본은 0.6 ~ 1.4, 0.05 간격입니다
- 작가마다 **슬라이더 + −/＋ 단추**. 슬라이더만으로는 폰에서 0.05 를 못 맞춥니다
- **숫자는 "손으로 정한 값"을 크게 보여 주고, 합 고정을 거쳐 실제로 나가는 값이 다르면
  옆에 작게 `→1.10` 처럼 덧붙입니다.** 나가는 값만 보여 주면 ＋ 를 눌러도 정규화가 도로
  깎아 **숫자가 안 움직이는 것처럼** 보입니다. 고장으로 보이는 자리입니다
- 범위를 좁히면 지금 섞고 있는 값도 바로 끌어들입니다
- "가중치 무작위로"로 한 번에 섞어 볼 수 있습니다
- **가중치 합을 작가 수로 고정**할 수 있습니다 (기본 켜짐). 다섯 명한테 전부 1.2 를 주면
  프롬프트가 작가 쪽으로 쏠려 구도·표정·의상 태그가 밀려납니다. 켜 두면 한 명을 올릴 때
  나머지가 조금씩 내려가서, "이 작가를 더 세게"가 다른 것을 망가뜨리지 않습니다.
  작가가 **혼자일 때는 맞추지 않습니다**, 나눠 가질 상대가 없는데 합을 맞추면 무조건
  1.0 이 되어 슬라이더가 죽은 것처럼 보입니다
- "작가 태그 칸에 넣기" 를 누르면 앞에 끼워 넣습니다. **다시 눌러도 쌓이지 않습니다**
  (앞서 넣은 조합을 갈아 끼웁니다. 안 그러면 누를 때마다 가중치가 몇 배가 됩니다)

가중치는 `숫자::태그::` 로 나갑니다. 1.0 인 작가는 문법을 붙이지 않습니다.

**이름이 숫자로 끝나는 작가는 조심해야 합니다** (`artist:119`, `as109` 처럼).
NAI 의 `숫자::` 는 여는 괄호가 아니라 **"여기서부터 뒤로 이 가중치"** 라는 뜻이고, 맨 뒤의
`::` 가 그것을 되돌립니다. 그래서 `::` 바로 앞에 숫자가 오면 **그 숫자가 새 가중치로
읽힙니다.**

| 쓴 것 | 무슨 뜻이 되나 |
|---|---|
| `1.2::artist:119::` | `artist:` 뒤로 **119배**. 그림이 깨집니다 |
| `artist:119::` | 그 뒤로 119배. 마찬가지로 깨집니다 |
| `1.2::artist:119, artist:meola::` | 둘 다 1.2배. 숫자 뒤가 쉼표라 안전합니다 |
| `{{{{artist:119}}}}` | 1.05⁴ = 1.2155배. 안전하지만 값이 조금 어긋납니다 |

앱이 알아서 피해 갑니다.

- 같은 가중치인 작가끼리 **한 무리로 묶고**, 이름이 숫자로 끝나는 작가를 앞에, 안전한
  작가를 **맨 뒤에** 세웁니다. 그러면 정확한 값으로 나갑니다
- 한 무리가 통째로 숫자로 끝나는 이름뿐이면 `숫자::` 를 쓸 수가 없어 **괄호**로 갑니다.
  한 겹이 1.05배라 정한 값에 딱 안 맞습니다
- 그때는 화면에 `artist:119 1.2→1.22` 처럼 **어긋난 값을 적어 줍니다.** 말없이 다른
  값으로 나가면 안 됩니다. 같은 가중치인 다른 작가를 하나 더 켜면 정확한 값으로 돌아옵니다
언더스코어는 띄어쓰기로 바꾸되 **괄호는 그대로** 둡니다. NAI 는 `{}` 와 `[]` 로 가중치를
조절하므로 `()` 는 글자입니다.

## 업데이트 알림

스토어를 안 거치니 아무도 안 알려 줍니다. 그래서 앱이 직접 **GitHub 릴리스**를 봅니다.

**조용히 알아서 깔리게는 못 만듭니다.** 안드로이드는 사이드로드한 앱을 설치할 때 반드시
사람이 확인 화면을 눌러야 합니다 (시스템 앱이나 기기 관리자면 예외인데, 이 앱은 거기
해당하지 않습니다). 그러니 앱이 할 수 있는 것은 **새 버전을 받아 두고 설치 화면까지
데려다주는 것**까지고, "설치" 를 누르는 것은 사람 몫입니다.

- 켤 때 **여섯 시간에 한 번** 봅니다. 켤 때마다 물으면 토큰 없는 한도(시간당 60번)를
  헛되이 씁니다. 설정에서 끌 수 있고, "업데이트 확인" 으로 바로 볼 수도 있습니다
- 새 버전이 있으면 **시작 화면 아래**에 뜹니다. 어디서 어디로 가는지, 무엇이 바뀌었는지,
  받을 파일이 몇 MB 인지. 알림창으로 가로막지 않습니다
- **"받아서 설치"** 를 누르면 앱이 APK 를 직접 받아 설치 화면을 띄웁니다. 브라우저로
  나갔다가 다운로드 폴더에서 파일을 찾아 누르는 왕복이 없어집니다
- 처음 한 번은 **"출처를 알 수 없는 앱" 권한**을 물어봅니다. 권한이 없으면 설치 화면을
  띄워도 아무 일이 안 일어나기 때문에, 먼저 설정으로 보내고 나서 다시 누르게 합니다
- APK 는 캐시 폴더에 받습니다. 안드로이드가 알아서 지울 수 있는 곳이라 용량이 쌓이지
  않습니다. 다른 앱에 넘길 때는 `content://` 로 바꿔서 넘깁니다. Android 7 부터
  `file://` 을 넘기면 앱이 죽습니다
- 앱에서 받다가 안 되면 **브라우저 링크라도 엽니다.** 여기서 막히면 업데이트할 길이 아예
  없어집니다. PC 미리보기에서도 이 길로 갑니다
- **어느 저장소를 볼지 설정에서 고릅니다.** peropix-mobile 과 peropix-Lkit-mobile 이
  같은 코드를 쓰기 때문에 어느 APK 를 깔았는지 앱이 알 수 없습니다. 직접 적을 수도
  있습니다. 저장소를 바꾸면 "언제 마지막으로 봤는지" 를 지웁니다. 안 그러면 여섯 시간
  동안 옛 저장소의 결과를 들고 있습니다
- "이 버전 건너뛰기" 는 그 버전만 안 알립니다. 그보다 새 버전이 나오면 다시 알립니다.
  "나중에" 는 이번에만 접습니다
- **토큰을 붙이지 않습니다.** 공개 저장소라 필요도 없고, 지시함용 토큰의 한도를 여기에
  쓸 일도 아닙니다
- `1.2.10` 을 `1.2.9` 보다 **크게** 봅니다. 글자로 비교하면 거꾸로 나와, 새 버전이 나와도
  모르게 됩니다
- 현재 버전을 모르면(PC 미리보기) 알리지 않습니다. 늘 "새 버전이다" 가 되어 알림이
  무의미해집니다. 깔린 버전은 안드로이드에 물어봅니다 (`App.getInfo`)

## 테스트: 조합과 깎기

**대량생성과 작가 태그는 시작 화면에서 갈립니다.** 조합이나 깎기로 한 장 뽑을 때마다
대량생성 화면으로 튕겨 나가던 것을 없앴습니다. 이제 **작가 태그 화면에 그대로 머문 채**
뽑고, 그림도 그 자리에 뜹니다. 평소 슬롯은 아예 건드리지 않습니다.

작가 태그만 갈아 끼우며 견주는 곳입니다. **조합**과 **깎기** 두 가지가 같은 판 위에서 놉니다.

### 테스트 설정: 작가 말고는 다 고정

그림체를 견주려면 **작가 말고는 아무것도 달라지면 안 됩니다.** 평소 쓰던 슬롯으로 돌리면
베이스·네거티브·인물 프롬프트가 전부 딸려 들어와, 그림이 달라진 것이 작가 때문인지 원래
프롬프트 때문인지 알 수 없습니다. 그래서 여기는 **자기 프롬프트 한 벌**을 따로 씁니다.

- **평소 것은 손대지 않습니다.** 뽑는 동안만 테스트용으로 바뀌고, 끝나면(실패해도) 슬롯·
  베이스·네거티브·인물·시드·배수가 **그대로 돌아옵니다**
- **구도** 일곱 판, 인물 상반신 / 카우보이 샷 / 얼굴 위주 / 배경만(복잡한 배경) /
  인물+복잡한 배경 상반신 / 인물+복잡한 배경 카우보이 샷 / 직접 적기.
  같은 작가라도 상반신이냐 전신이냐로 인상이 달라져서, 구도를 고정해야 작가 사이의
  차이만 남습니다. 배경이 복잡한 판을 따로 둔 것은 **인물만 잘 그리고 배경은 못 그리는
  작가가 흔해서**입니다
- 배경만 보는 판에는 인물을 안 싣습니다. 실으면 사람이 나와 배경을 가립니다
- **인물·품질·네거티브**를 직접 고칩니다. 품질 칸에 화풍을 건드리는 말(수채·러프 같은)을
  넣으면 작가 차이가 덮입니다
- 칸을 누르면 **대량생성과 같은 전체화면 편집기**가 열립니다. 두 줄짜리 칸에서 긴
  프롬프트를 고치는 것은 폰에서 사실상 불가능합니다. 복사·되돌리기·글자 수도 없습니다
- **이미지 설정도 따로 듭니다**: 모델 · 샘플러 · UC 프리셋 · 퀄리티 · 크기 · 스텝 ·
  가이던스 · 가이던스 리스케일 · Variety+ · 투명 배경 · Straight Alpha.
  모델이나 크기를 바꾸면 그림체 인상이 통째로 달라져서 여기서 고를 수 있어야 하는데,
  대량생성 값을 직접 고치면 "테스트 좀 해 봤다가 평소 설정이 바뀌어 있는" 일이 됩니다.
  비워 두면 대량생성 값을 그대로 쓰고, 실제로 나갈 값을 한 줄로 적어 줍니다.
  모델이 못 하는 것(Variety+ · 투명 배경)은 여기서도 잠급니다. 기준은 대량생성 모델이
  아니라 **테스트에서 실제로 쓸 모델**입니다
- 저장 설정(형식 · 품질 · 생성 정보 지우기 · 자동 저장)과 인핸스 설정은 **없습니다.**
  그림이 달라지는 값이 아니라 뽑은 뒤를 다루는 값이라, 테스트에서 따로 들 이유가 없습니다.
  배수도 없습니다. 테스트은 조합마다 한 장씩 뽑는 것이 전제라, 한 조합에 여러 장이 나오면
  어느 그림에 매긴 별점인지가 어긋납니다
- 구도 태그는 **실제로 살아 있는 것만** 씁니다. Danbooru 에서 버려진 태그(이미지 수 0)는
  NAI 도 모릅니다. `detailed_background` 가 그렇게 죽어 있어 구체적인 배경 태그로 바꿔
  두었습니다. 기본 인물은 쓰는 사람이 직접 준 것이라 그대로 둡니다
- 한 번 켠 적 있는 폰에는 **옛 기본 인물**이 저장돼 있습니다. 손대지 않은 것이면 새
  기본값으로 갈아 끼웁니다. 안 그러면 "기본값을 바꿨다는데 왜 그대로냐" 가 됩니다

### 조합: 무작위 가중치로 여러 세트

고른 작가들에게 **무작위 가중치**를 여러 벌 매겨 한 번에 뽑습니다. 어느 배합이 좋은지는
눈으로만 알 수 있으니, 손으로 슬라이더를 옮기는 것보다 여러 벌을 뽑아 견주는 편이 빠릅니다.

- 가중치는 서랍에서 정한 **범위 안에서** 무작위로 매겨집니다
- 같은 배합이 두 번 나오지 않습니다 (Anlas 를 헛되이 씁니다)
- **시드 고정**이 기본입니다. 끄면 배합과 시드가 같이 달라져 무엇 때문에 달라졌는지
  알 수 없습니다
- 뽑은 그림이 **조합마다 나란히** 뜹니다. 마음에 든 것은 "이걸로"를 눌러 섞기로 옮깁니다.
  숫자를 손으로 옮겨 적게 하면 반드시 틀립니다
- **조합마다 여러 장** 뽑을 수 있습니다 (1~4장). 한 장만 보고 정하면 그 시드가 운이 좋았던
  것인지 알 수 없습니다. 한 조합 안에서는 시드가 서로 다르고, **조합끼리는 같은 시드 묶음**을
  씁니다. 안 그러면 비교할 수가 없습니다
- 별점은 **조합 하나에 하나**입니다. 그 조합의 어느 장에 매기든 같은 점수가 됩니다.
  장마다 따로 매기게 하면 몇 번을 매겨야 하는지 알 수 없어집니다
- 딱 맞는 게 없으면 **별점(1~5)** 을 매기고 "점수 반영해서 다시 뽑기". 작가마다
  점수로 가중 평균한 가중치를 구해 그 근처에서 다시 뽑습니다. 5점을 준 조합의 값이 가장
  크게 당겨지고 1점을 준 값은 거의 안 당겨집니다
- 작가를 켜고 끄는 판단은 하지 않습니다. 조합은 같은 작가에 가중치만 바꿔 가며 뽑으므로
  모든 작가가 모든 조합에 들어 있고, 그러면 작가별 평균 점수가 전부 같아져 신호가
  되지 않습니다. 필요 없는 작가는 가중치가 최소값으로 내려가며 자연히 빠집니다

### 깎기: 범인 찾기

작가 태그를 20개 넣고 뽑았는데 그림의 어떤 요소가 **누구 때문인지** 모를 때 씁니다.
후보는 **서랍 · 섞기 · 작가 태그 칸**에서 불러와 눌러서 고릅니다 (직접 적어 더할 수도
있습니다). **최대 20명**이고, 차면 나머지는 눌리지 않습니다. 눌리는데 안 담기면
고장으로 보이기 때문입니다.

**가짓수가 안 터지게 하는 방법은 탐색하지 않는 것**입니다. on/off 20개는 2²⁰ 이고,
거기에 가중치 5단계를 곱하면 5²⁰ 이라 훑을 수 없습니다. 그래서 **"누구인가"와 "얼마나"를
절대 같이 돌리지 않습니다.**

| | 방식 | 이미지 수 |
|---|---|---|
| 1단계 **누구인가** | 가중치를 전부 1.0 으로 묶고 on/off 만 이분 탐색 | 20명 → **5라운드** |
| 2단계 **얼마나** | 범인 한 명만 1차원으로 훑기 | **5장** |

합쳐서 **10장 안팎**이면 끝납니다.

- **넣기가 아니라 빼기**로 가릅니다. 절반만 넣고 뽑으면 그림이 통째로 달라져 무엇 때문에
  달라졌는지 알 수 없습니다. 전체를 유지한 채 절반을 **빼야** 나머지 화풍이 남은 상태에서
  그 요소만 사라졌는지 보입니다
- **시드를 고정**합니다. 깎기에서 시드는 설정이 아니라 전제입니다. 시드가 바뀌면 그림이
  달라진 것이 태그 때문인지 시드 때문인지 구분할 방법이 없습니다
- 첫 라운드는 **대조군**입니다 (아무것도 빼지 않은 원래 조합). 이것이 없으면 "그 요소가
  있다/없다"를 무엇과 견주어 판단할지가 없습니다
- **교차 확인**: 양쪽을 각각 빼 봅니다. 이미지 수가 두 배로 늘지만, 왼쪽을 빼도 남고
  오른쪽을 빼도 남으면 그 요소는 **여럿이 함께 만든 것**임을 알아냅니다. 이것을 알려 주지
  않으면 이분 탐색을 계속 돌리며 헤매게 됩니다
- 실행 전에 **이미지 수와 Anlas** 를 적어 줍니다
- 잘못 봤으면 **되돌리기**. **그만두면 원래 슬롯이 돌아옵니다**, 남의 작업을 말없이
  날리지 않습니다

깎기는 라운드마다 **슬롯으로 구워** 기존 생성 경로를 그대로 탑니다. 뽑고 결과를 본 뒤
돌아와 "남아 있다 / 사라졌다"만 누르면 후보가 절반씩 줄어듭니다.

### 확대 보기 (조합·깎기 전용)

뽑은 그림을 누르면 크게 뜹니다. 대량생성의 뷰어와 **아래가 다릅니다**.

- **별점이 그림 아래**에 붙습니다. 크게 봐야 점수를 제대로 매길 수 있는데, 작은 썸네일
  옆에서만 매기게 해 두면 확대했다 닫았다를 반복하게 됩니다
- **좌우로 밀면 그 판에서 뽑은 것끼리** 넘어갑니다. 견주려고 뽑은 것들이니 나란히 오갈 수
  있어야 합니다
- 인핸스·업스케일·이전/다음 슬롯 줄은 **뺐습니다**. 여기는 슬롯 개념이 없습니다.
  그 자리에 **어떤 조합인지**(작가와 가중치)를 적습니다
- 여기서 매긴 점수는 목록의 별점과 **같은 값**입니다. 닫으면 그대로 반영돼 있습니다

### "이런 작태는 어떠세요?"

두 군데에 있습니다.

- **앱을 켤 때** 시트로 다섯 명. 뽑고 난 뒤가 아닙니다. 다 뽑고 나면 그 판은 이미
  끝났고, 새 작가는 **다음 판을 짜기 전에** 알아야 쓸모가 있습니다
- **작가 태그 → 추천 탭**에서 언제든 열 명. "다시 뽑기"로 새 얼굴을 봅니다.
  시트를 "다시 보지 않기"로 꺼 두어도 여기서는 볼 수 있습니다

둘은 **같은 코드로 그립니다.** 두 벌로 두면 한쪽만 고쳐져 팝업과 메뉴가 다른 것을
보여 주게 됩니다. 최소 이미지 수도 한 곳에서 정한 값을 양쪽이 함께 씁니다.

- 근거는 **그림 100장 이상**입니다. 그 아래는 NAI 가 배울 거리가 없어 태그를 넣어도
  그림에 안 나옵니다. 권해 봐야 헛걸음을 시키는 셈입니다. 시트에서 300 · 1000장으로
  올릴 수 있습니다 (탭에서는 5000장까지)
- 100장 이상인 작가가 **약 2만 4천 명**이라 한 번에 다 받을 수 없습니다. 무작위
  쪽(페이지)을 받아 그중에서 다시 고르므로 **켤 때마다 다른 얼굴**이 나옵니다
  (`order=random` 은 매번 같은 것을 돌려주어 쓸 수 없었습니다)
- 이미 서랍에 있는 사람과 버려진 태그는 뺍니다. 같은 사람을 두 번 권하지 않습니다
- **장르도 함께 잽니다**. 썸네일을 받는 그 응답에서 재므로 부르는 횟수가 늘지 않습니다
- **이름을 누르면 "찾기"로 넘어가 그 작가가 바로 펼쳐집니다**: 통계·특징 태그·그림을
  다 보고 나서 담을지 정합니다. 권해 놓고 "더 볼 방법은 알아서 찾으세요"는 불친절합니다.
  시트에서 눌러도 시트가 닫히며 넘어갑니다
- "다른 작가"로 다시 뽑고, "담기"로 바로 서랍에 넣습니다 (장르까지 같이 담깁니다)
- 첫 실행(키를 아직 안 넣었을 때)에는 안 뜹니다. 그때 할 일은 키 넣기입니다
- "다시 보지 않기"로 끕니다

### 이 검사가 무엇을 지키나

`www/js/nai-payload.js` 는 NovelAI 웹이 실제로 보내는 요청을 **그대로 재현**합니다.
프리셋 접미사, `tag_hint` 번호표, 모델별 능력 차이(V5 는 Variety+ 가 없고 스케줄러를
고를 수 없다 등), 따옴표 → `teXt:` 자동 조립 같은 것들이 전부 여기 걸려 있습니다.

**조금만 어긋나도 오류가 나지 않고 그냥 다른 그림이 나옵니다.** 눈으로는 못 잡습니다.
그래서 기준 페이로드 138 건을 저장소에 넣어 두고 기계적으로 대조합니다
(`tools/reference_payloads.json`). Anlas 계산도 169 건을 대조합니다.
이 숫자가 틀리면 "무료인 줄 알았는데 차감됐다" 가 됩니다.

실제로 이 대조가 `text:` 정규식의 대소문자 무시 플래그 누락을 잡았습니다.
파이썬 쪽은 플래그가 패턴 문자열 밖에 있어서 옮길 때 조용히 빠졌던 것입니다.

> **`backend.py` 는 이 저장소에 없습니다.** PeroPix 데스크톱판의 백엔드이고,
> 이 앱은 거기서 NAI 생성 경로만 떼어 온 것입니다. 기준값은 이미 커밋돼 있으므로
> 데스크톱판 없이도 `npm test` 는 그대로 돌아갑니다.
>
> 데스크톱판을 가지고 있고 그쪽 NAI 코드를 고쳤다면, `tools/export_tables.py` 와
> `tools/capture_reference.py` 로 기준값을 다시 뽑아 맞출 수 있습니다.
> (두 스크립트는 `backend.py` 를 불러오므로 데스크톱판 폴더 안에서 돌려야 합니다.)
